# 心动像素 Pixel Heart ❤

一款**情侣双人同屏合作**的微信小游戏,复古像素风格,纯 Canvas 编写、无任何外部图片/音频资源,代码即玩。

**4 关连续挑战,每关难度递增、掉落物种类不同**,通关看默契,全通拿评级!

**视听**:发光像素精灵 + 拖尾残影、接中冲击波与心形粒子、三层视差星空与流星、
每关主题色平滑过渡、时间告急红脉冲、过关彩纸礼花,以及**程序化合成的 8-bit 音效**
(接心音阶随连击升高 / 金心琶音 / 彩虹上升音 / 炸弹爆炸 / 心碎 / 过关号角,菜单右上角可开关)。

```
你 ← 守左边    |    TA → 守右边
────────────────────────────────
  第 1 关  心动初识   只有红心,热身上手
  第 2 关  甜度加倍   + 金心(+3)、坏心情炸弹
  第 3 关  默契挑战   + 彩虹心(+5 并清除全场炸弹)
  第 4 关  灵魂之约   全掉落物,速度/密度终极考验
────────────────────────────────
每 10 连击奖励爱心;每过一关奖励爱心(上限 5)
爱心归零 → 止步结算;4 关全通 → 通关评级
```

- 双人同屏:两人各守一侧,双手**可同时操作**(多点触控)
- 实在没人陪?一个人也能玩,练手即可
- **难度三维可调**(菜单里各 4 档,选择自动保存):**下落速度** / **心的数量** / **移动轨迹**
- 真机带震动反馈(接中轻震 / 连击中震 / 心碎强震)

## 一、文件结构

```
pixel-love/                  ← 微信小游戏工程(直接导入微信开发者工具)
├── game.js                  ← 主入口 / 编排层:初始化、状态机、输入、帧循环
├── src/                     ← 各职责模块(被 game.js 用 require 引入)
│   ├── core.js              画布 / 缩放 / 调色板 / 像素字体 / 绘制工具 / 存储 / 震动
│   ├── config.js            关卡数值、难度档位(速度/数量/轨迹)、评级、判定半径 ← 调参入口
│   ├── audio.js             程序化 8-bit 音效(零音频资源)
│   ├── sprites.js           掉落物精灵预烘焙(离屏贴图 + 光晕)
│   ├── entities.js          掉落物「角色」:红心 / 金心 / 彩虹心 / 炸弹
│   ├── fx.js                粒子 / 飘字 / 冲击波 / 涟漪 / 彩纸 / 星空流星
│   ├── background.js        背景烘焙 / 关卡主题过渡 / 地面落带
│   ├── hud.js               顶部信息栏(爱心 / 分数 / 倒计时 / 连击)
│   └── screens.js           菜单(含三个难度档位)/ 过关面板 / 结算面板
├── preview/                 ← 浏览器试玩(仅本地体验用,已被打包忽略)
│   ├── preview.html         双击即可在浏览器试玩
│   └── wx-shim.js           把 wx API + require 映射到浏览器 DOM
├── game.json                ← 竖屏配置
└── project.config.json      ← 开发者工具工程配置
```

> **同一份代码双端运行**:微信小游戏原生支持 `require()`;浏览器里由 `wx-shim.js`
> 提供同名桥接(`src/*.js` 挂载到 `window.__MODS__`,`require('./src/x.js')` 返回它),
> 因此所有模块源码在两端**零改动**。

### 模块职责边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `game.js` | 状态机、输入派发、帧循环、对局规则(加减分/爱心/连击奖励) | 具体绘制、配色、发声 |
| `entities.js` | 每个掉落物的外观、下落摇摆、被接住与落地的表现和音效 | 生成节奏、命中判定 |
| `screens.js` | 菜单/过关/结算的版面与按钮命中区域 | 状态切换(由 game.js 决定) |
| `config.js` | 所有可调数值 | 任何逻辑 |

想加新掉落物:在 `entities.js` 里加一个继承 `Item` 的类(实现 `drawBody` / `onCatch` / `onLand`),
再到 `Entities.spawn` 里按权重分支即可,`game.js` 完全不用动。

## 二、快速体验(浏览器)

直接双击打开 `pixel-love/preview/preview.html`(或拖进任意浏览器)。
桌面端用鼠标即可模拟点击;真触屏设备上支持双指同时操作,可模拟双人场景。

## 三、在微信开发者工具中运行(真机预览)

1. 下载并安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html);
2. 打开工具 →「小程序」→「导入项目」;
3. 目录选择本仓库的 **`pixel-love`** 文件夹;
4. AppID:无账号可选 **「测试号」(游客模式)**;有账号则填你的小游戏 AppID;
5. 导入后点击「编译」即可在模拟器游玩,点「预览」扫码即可在手机上真机试玩(双人同屏多点触控 + 震动)。

> 提示:小游戏类目与小程序类目不同,若要**发布上线**,需在
> [微信公众平台](https://mp.weixin.qq.com) 注册 **「小游戏」** 类型账号获取正式 AppID,
> 并在 project.config.json 中替换 `"appid"`。

## 四、关卡与规则明细

| 掉落物 | 操作 | 结果 |
| --- | --- | --- |
| 红色爱心 | 点击接住 | +1 分,连击 +1 |
| 金色爱心(第 2 关起) | 点击接住 | +3 分,连击 +1 |
| 彩虹心(第 3 关起) | 点击接住 | +5 分,连击 +1,**清除全场炸弹** |
| 黑紫炸弹(带火花) | **不要点**,让它落地 | 落地无害消失,但连击清零 |
| 黑紫炸弹 | 误点 | 爆炸!爱心 -1,连击清零,屏幕红闪 |

- 红心/金心/彩虹心落地未接住 → 爱心 -1(心碎)
- 爱心归零 → 提前止步结算;每关时间用完 → 过关(第 1~3 关)或通关(第 4 关)
- 结算给出:总得分、最高连击、命中率、默契评级(S/A/B/C/D)+ 一句情话
- 历史最高分本地自动保存,下次打开仍在

### 各关参数一览(`src/config.js` 的 `LEVELS` 数组)

| 关卡 | 名称 | 时长 | 生成间隔(秒) | 下落速度 px/s | 炸弹权重 | 金心权重 | 彩虹权重 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 心动初识 | 28s | 0.62 → 0.44 | 215 → 340 | 0 | 0 | 0 |
| 2 | 甜度加倍 | 30s | 0.54 → 0.38 | 260 → 405 | 0.10 | 0.10 | 0 |
| 3 | 默契挑战 | 34s | 0.46 → 0.32 | 305 → 470 | 0.18 | 0.11 | 0.045 |
| 4 | 灵魂之约 | 40s | 0.42 → 0.28 | 350 → 545 | 0.24 | 0.12 | 0.055 |

> 生成间隔 / 下落速度在本关内随时间从「开始值」爬升到「终值」;
> 权重为各掉落物占生成量的比例,红心占剩余部分。
> 上表为**基准值**,实际值还要乘以下面难度档位的倍率。

### 难度设置(菜单里三组,各 4 档)

觉得太慢、太挤还是太飘?菜单里有三组开关,选择后自动保存到本地,下次打开仍生效。

**① 下落速度** —— 掉得多快

| 档位 | 速度倍率 | 生成间隔倍率(顺带收紧,避免屏幕变空) |
| --- | --- | --- |
| 轻松 | ×0.95 | ×1.10 |
| 标准 | ×1.30 | ×1.00 |
| 刺激 | ×1.75 | ×0.92 |
| 疯狂 | ×2.30 | ×0.85 |

**② 心的数量** —— 一次来多少

| 档位 | 生成间隔倍率 | 单侧通道同时存在上限 |
| --- | --- | --- |
| 稀疏 | ×1.30 | 3 |
| 适中 | ×1.00 | 4 |
| 密集 | ×0.78 | 5 |
| 爆满 | ×0.62 | 6 |

**③ 移动轨迹** —— 横向怎么飘(横向位移 = `sin(主波) × amp + sin(副波) × wob`)

| 档位 | 表现 | amp | wob |
| --- | --- | --- | --- |
| 直落 | 垂直落下,最好预判 | 0 | 0 |
| 摇摆 | 左右轻摆 | 1.0 | 0 |
| 蛇形 | 大幅 S 形横扫 | 3.4 | 0 |
| 乱流 | 主波 + 副波叠加,毫无规律 | 2.0 | 1.2 |

> 三组是**相乘叠加**的:比如「疯狂 + 爆满 + 乱流」= 又多又快还不走直线,慎选 😈
> 横向位移会被夹在本侧通道内(不至于飘到对面「串台」)。

## 六、技术要点

- 主循环 `requestAnimationFrame`,`dt` 限幅防切后台跳帧;
- 状态机:菜单 / 游戏中 / 过关面板 / 结算(通关与止步两套文案);
- 触控用 `wx.onTouchStart` 的 `changedTouches` 遍历,天然支持多点;
- `wx.onShow / onHide` 自动暂停/恢复;
- **模块化**:`game.js` 只做编排,绘制/角色/特效/音效/背景/HUD/界面各自独立成 `src/` 下的模块,
  通过 CommonJS `require` 组合;浏览器端由 `wx-shim.js` 提供同名桥接,源码零改动;
- **性能**:所有掉落物与光晕在启动时预烘焙成离屏贴图(`buildSprites()`),运行时只做 `drawImage`;
  背景渐变/极光/网格缓存到离屏画布,仅关卡切换的 0.7s 过渡期逐帧重建;
- 全部像素图形用「01 字符画 + 逐格 fillRect」程序化绘制,零资源依赖(彩虹心逐格循环取色);
- **音效**:`wx.createWebAudioContext`(浏览器降级为 `AudioContext`)实时合成方波/三角波与噪声,
  零音频文件;任一环节失败都静默降级,不影响游戏;
- 震动用 `wx.vibrateShort`(web 预览降级为 `navigator.vibrate`)。
